| D27 | 2026-10-01 | YouTube via the official Data API only: metadata + description, then follow the description's research links; no video download, no transcript scraping | YouTube's terms forbid downloading and the API gives captions only to the video owner; descriptions often link the underlying paper/code |
| D28 | 2026-10-01 | Adopt from the user's Idea Extractor: sources.txt list, channel expansion (official API), maturity badge, Markdown/Obsidian notes; not yt-dlp subtitles or Vision OCR | Reuse proven workflow; keep YouTube terms and the no-fabrication / cost rules |
| D29 | 2026-10-02 | **Supersedes D27's "no transcript scraping"**: a video is read through its captions via yt-dlp (`--skip-download`, subtitles only; media is still never downloaded), behind `discovery.youtube_transcripts` (default **off**) | Measured: 150 video descriptions triaged → **0 strategies** ($0.26). A video's strategy is spoken, so description-only reading cannot work. The user explicitly approved this reversal; YouTube ToS compliance is now their call, and one config line reverts to D27 behaviour |
| D30 | 2026-10-02 | Work identity derived from any source URL (arXiv/DOI), **version suffix stripped** so `1304.6846v2` and `1304.6846` share one root evidence | Without it the same paper read via abstract page and PDF counted as two studies — inflating "independent replication" and any target that counts distinct ideas |
| D31 | 2026-10-02 | Continuous harvest: rounds until N distinct ideas are PROMISING, target measured after scoring and dedupe; daily-budget exhaustion **sleeps to the reset** instead of stopping; every stop reason is explicit | The budget is a hard cap, so "continuous" can only mean resuming across day boundaries. Counting raw extractions would be meaningless (re-reading one paper would inflate it) |
| D32 | 2026-10-02 | `parameter_simplicity` and the `PROMISING` threshold were left alone (0 and 70 respectively) after measuring why the score is low | The 0 is honest: that strategy uses 4 indicator families and ~8 threshold comparisons. Lowering the bar to make a loop look successful would defeat the gate's purpose |
| D33 | 2026-10-02 | GitHub code channel via the public REST API, **off by default** (`discovery.github_enabled`), metadata only — never clone or download code; licence recorded with the candidate | Without a key GitHub search allows only 60 requests/hour, so joining every run would exhaust it. Recording the licence answers spec §11's licence-tracking requirement before anything is reused |
| D34 | 2026-10-02 | Unattended operation is a **daily Windows Scheduled Task**, not a long-running loop | The daily AI budget is a hard cap, so an in-process loop would have to sleep for hours across the reset; a laptop that sleeps or reboots would silently stop it. A daily task resumes the same campaign with documents and AI answers already cached, so nothing is paid twice |
| D35 | 2026-10-02 | Source selection prefers candidates whose own abstract reports robustness evidence (out-of-sample, replication, cross-market, costs), as a **tie-breaker inside a tier** — never a tier promotion | Measured (docs/GATE_CALIBRATION.md): the best idea misses the PROMISING gate by 6.31 points and `expected_robustness` is 0.00 on 14 of 15 ideas; that component scores the share of exactly those evidence signals. It reads only what the source already claims, so it invents nothing |
| D36 | 2026-10-02 | The 70 gate and the component weights stay unchanged, despite nothing having passed | The calibration shows the shortfall has an honest cause (no robustness evidence; complex strategies), and the reachable margin is ~1 point. Lowering the bar so existing ideas pass would destroy the gate's meaning; the fix is better sourcing and better selection |
| D37 | 2026-10-02 | **Supersedes D36's "leave it alone" on the threshold only:** `quality_gate.promising` 70 → **60** (the old `research_further` line). Weights unchanged; `min_coverage_for_gate` unchanged | Measured (docs/GATE_CALIBRATION.md): several components cap below 1.0 by design (`edge_vs_cost` 0.6, `data_availability` 0.7, `exit_executability` 0.7, `liquidity` 0.8), so a *perfect* idea scores 88.2, not 100 — the effective bar was ~79% of achievable, not 70%. At 70 nothing passed; at 60 the nine best-specified ideas surface as PROMISING so the deepening stage can work on them. **Trade-off accepted explicitly: at 60, eight of those nine have no robustness evidence.** Ideas still reach the backtest queue only through the separate handoff rule (completeness ≥ 60, normalized ≥ 55, coverage ≥ 0.6, data availability ≥ 0.4) |
| D38 | 2026-10-02 | Algorithm-shaped strategies get their own representation: `ideas.strategy_kind` (BAR_RULE / ALGORITHM / PORTFOLIO_WEIGHT / MACHINE_LEARNING) and `ideas.algorithm_rule`, schema **v4 → v5** (additive). `RULES_NOT_QUANTIFIABLE` now fires only when there is no rule of *any* kind | Measured: the PAMR paper (*Passive Aggressive Mean Reversion*) states its decision as a portfolio-weight update equation, so `signal`/`entry_rule`/`exit_rule` were legitimately UNKNOWN, completeness reached 10%, and **four fully specified ideas were hard-failed**. The anti-fabrication rule was right (the model refused to invent a bar-rule); the schema had nowhere to put an algorithm, so it silently discarded that class of research |
| D39 | 2026-10-02 | The harvest loop **directs its own later rounds**: follow-up queries are derived from the campaign's own extracted strategy families (weighted by how much was found), their asset classes, and templates aimed at the gate's measured gaps | The loop could run rounds and respect budgets but could not decide what to look for next, so the static plan was exhausted after round 1 (measured: rounds 2 and 3 of campaign 9 both reported `0 new papers found`). Nothing is invented — no extracted family means no direction. Verified live: round 2 followed up on *"deep hedging out of sample evidence"* and found 29 new papers |
| D40 | 2026-10-02 | A spent **search** allowance is a per-round state, not the end of the campaign (searches cost HTTP requests, not AI money). Genuine ceilings — campaign AI cost, urls, documents — still stop the run | Measured: campaign 5 spent 97 of 100 searches in one round and the run ended, although the daily cost budget was untouched and thousands of unused query combinations remained |
| D41 | 2026-10-04 | Every PDF page also gets a pdfminer layout reading (`HandlerResult.alt_blocks`); grounding accepts a quote found in either reading of the pages the AI saw. The AI's input is unchanged | The two-column failure is at word-extraction time (pdfplumber merges characters across the gutter), so the fix belongs at that layer, not in a fifth tuning of the gutter probe; both readings are faithful renderings, so no unstated text can pass |
| D42 | 2026-10-04 | Evidence signals (out-of-sample, costs, code, sample period, cross-market) are read from the whole document, only from sentences where the source describes its own work, outside the reference list; each stored verbatim as an `EVIDENCE:*` fact | Scoring saw only abstract + summary + the AI's quotes, so robustness reported in a paper's body scored 0 (0.00 on 14 of 15 ideas). A measurement fix, not a threshold change |
| D43 | 2026-10-04 | An approximately matched quote must contain the value's numbers itself | Found by a test: "six month" aligned with the source's "twelve month" and the value "6-month" passed via an unrelated "6" on the page |
| D44 | 2026-10-04 | The harvest submits eligible PROMISING ideas to the backtest queue after every round; `qsd queue --why` reports what blocks the rest | The harvest counted PROMISING ideas but never submitted any, so the queue could not fill however good the ideas were |
| D45 | 2026-10-04 | Evidence sentences that negate or defer the work ("no", "not", "avoid", "ignore", "exclude", "future research", "beyond the scope") count for nothing; cross-market needs "international markets/sample/evidence/data", not the bare word; "out- of-sample" split by a line break is recognised | Hand check of all 30 live `EVIDENCE:*` sentences after D42: 24 correct, 6 wrong — three negated costs ("we assume no transaction cost", "we avoid incorporating…"), one future-work costs sentence (which alone moved ideas 12 and 13 to PROMISING), one counterfactual "international… markets" and one company name ("Crown Castle International Corp."). Pinned as a regression test with the real sentences |
| D46 | 2026-10-04 | `data_availability` rates commodities, volatility and multi-asset like other bar-data classes (0.7) and fixed income at 0.6 (index and yield series free, bond-level prices not); options stay 0.4; intraday stays unassessed | Measured: idea 1 (completeness 100, normalized 61.7) was blocked from the backtest queue only by "data availability not established" because its asset classes fell outside the heuristic's list, not because data is scarce. A coverage gap, not a threshold change |
| D47 | 2026-10-04 | `qsd reextract --source/--idea` asks the model again with the current prompt and updates the source's ideas **in place** (matched by strategy name: same id, history, campaign). New strategy names become new ideas; old ideas the new answer does not name are reported and left untouched; an empty answer changes nothing; submitted ideas are never changed. Dry run unless `--yes`; a source already extracted with the current prompt is skipped (the same question returns the same cached answer) | Ideas 12, 13 and 15 lack instrument and rules from an extraction made with an older prompt; `qsd extract` only takes local files and would have created duplicate ideas beside the old ones |
| D48 | 2026-10-04 | **Supersedes D37:** `quality_gate.promising` 60 → **70**. Weights, caps and the handoff rule unchanged | Measured on all 31 live ideas after D41–D46 (docs/GATE_CALIBRATION.md, 2026-10-04 section): no idea scores between 63.7 and 70.8. The 61–64 cluster (ideas 1, 5–9, 21, 22) has `expected_robustness` 0 on every idea; the ideas at 70+ (20: 78.1, 27: 71.8, 28: 71.6, 10: 70.8 under review) have reported out-of-sample evidence or near-complete rules with strong rationale. D37's reason (robustness unmeasurable) is gone, and its other reason was wrong: the deepen stage works on RESEARCHING as well as PROMISING ideas, so 55–70 ideas are still followed up. The known scoring quirks do not decide any outcome at 70: treating "costs discussed" as unassessed moves scores by ≤ 1.6; dropping `parameter_simplicity` would lift ideas 5–9 to 68.3 (their complexity is real: 4 indicator families, ~9 thresholds) and 21/22 to 69.0. | D49 | 2026-10-04 | The prompt-injection detector flags "place/submit/execute a trade/order" only when addressed to the reader ("you must", "please", "now", "immediately"), not as bare trading talk. | D50 | 2026-10-05 | **Setup readiness is reported separately from completeness** (`scoring/readiness.py`, schema **v5 → v6**: `ideas.setup`, `ideas.fill_origins`). `formalization_completeness` stays the honest measure of what the source wrote down and keeps feeding the quality score; `setup_readiness` asks whether the idea can become a runnable setup. | D51 | 2026-10-05 | A silent **exit** may be derived (risk control, not edge) and is labelled DERIVED; entry stays source-only. | D52 | 2026-10-05 | **Handoff eligibility asks whether the setup is runnable**, not how many fields the source filled: source-stated entry, not too thin, setup runnable (replaces `completeness ≥ 60` and the literal `instrument == UNKNOWN`).
